# Goalkeeper AMP 接口约定草案

日期：2026-11-01  
状态：待 Part A 和 Part B 共同确认，确认后作为第一版实现与验收依据。

Part A 负责 AMP 学习算法与训练集成，Part B 负责参考数据与环境接口。本文约定双方交换的数据、时间语义、类别含义和 reset 行为，使两个部分可以独立开发后进行联调。函数名称和接口均为拟定方案，不表示已经实现。

## 实现范围

- 使用串联 K1，22 个关节。
- 一个 Actor，六个按动作类别路由的判别器。
- 单帧 AMP 特征只包含绝对关节角，连续两帧构成一个运动样本。
- Actor 和 Critic 的输入保持现有定义，不额外拼入 AMP 特征或真实动作类别。
- 保留普通 PPO 任务，新增独立 AMP 任务。
- 第一版不加入镜像、随机动作变速、并联控制或真实视觉改造。

## 特征与时间约定

`N` 表示并行环境数量，`B` 表示一次 expert 采样的样本数量。

| 项目 | 第一版约定 |
| --- | --- |
| 关节数量 | 22 |
| 关节顺序 | `K1_JOINT_ORDER` |
| 数值含义 | 绝对关节角，不减默认姿态 |
| 单位 | 弧度 `rad` |
| 数据类型 | `torch.float32` |
| 环境单帧形状 | `(N, 22)` |
| 两帧间隔 | `env.step_dt`，当前为 `0.02 s` |
| 窗口顺序 | 旧帧在前，新帧在后 |
| 两帧窗口形状 | `(B, 2, 22)` 或 `(N, 2, 22)` |
| 判别器输入 | Part A 按帧展平为 `(B, 44)` 或 `(N, 44)` |
| 统计归一化 | 由 Part A 统一管理，Part B 输出原始物理量 |

关节顺序的唯一来源为 [k1_constants.py](../src/booster_mjlab/robots/booster_k1/k1_constants.py) 中的 `K1_JOINT_ORDER`。环境端应按关节名称获取并排列数据，不能假定仿真内部顺序一致，也不能仅截取前 22 列。

参考采样与实际运动必须使用相同时间间隔。如果控制周期发生变化，应将新的 `env.step_dt` 传给参考采样器；不能只修改环境频率而继续使用旧的 expert 时间间隔。

## 环境单帧观测接口

Part B 新增独立 observation group，Part A 从下列位置读取当前实际关节角：

```python
obs["amp"]
```

| 属性 | 约定 |
| --- | --- |
| 形状 | `(N, 22)` |
| 类型 | `torch.float32` |
| 设备 | 与环境设备一致 |
| 内容 | 按 `K1_JOINT_ORDER` 排列的实际绝对关节角 |
| 历史 | 不叠加历史，由 Part A 管理 |
| 预处理 | 不减默认姿态，不做统计归一化，不增加观测噪声 |

该组不参与 Actor 或 Critic 的输入拼接。Part A 若将数据转到另一训练设备，应保持特征、标签和 mask 的设备一致。

## 动作类别接口

Part B 提供读取函数，封装环境内部的类别存储方式。Part A 不直接读取 `_full_goal_shots` 等私有属性。

拟定签名如下，仅表示接口，不包含实现：

```python
def get_amp_motion_ids(env) -> torch.Tensor:
    ...
```

返回值为 `(N,)` 的 `torch.int64` 张量，位于环境设备上，取值范围为 `0` 到 `5`。

| motion_id | clip 名称 |
| --- | --- |
| 0 | `lefthand` |
| 1 | `righthand` |
| 2 | `leftjump` |
| 3 | `rightjump` |
| 4 | `leftstep` |
| 5 | `rightstep` |

类别在一个回合内保持不变，reset 时允许重新采样。类别是训练端路由判别器的标签，不额外提供给 Actor，也不从机器人当前姿态反推。

读取函数返回的张量可能引用环境内部缓冲。Part A 如需跨 `env.step()` 保留旧类别，应在 step 前使用 `.clone()` 保存，避免 reset 原地更新标签。

Part B 负责核对类别与机器人前方拦截平面的运动需求是否一致。不能仅凭球门平面的落点，将经过机器人时的高球标成低球或将左右类别错配。

## 参考窗口采样接口

Part B 按 Part A 请求的类别返回参考关节角窗口。拟定签名如下：

```python
def sample(
    motion_ids: torch.Tensor,
    *,
    frame_dt: float,
) -> torch.Tensor:
    ...
```

此函数作为参考采样器的方法使用，即 `sampler.sample(...)`。

| 项目 | 约定 |
| --- | --- |
| 输入类别 | `motion_ids`，形状 `(B,)`，类型 `torch.int64`，取值 `0` 到 `5` |
| 输入间隔 | `frame_dt`，单位秒，必须为有限正数 |
| 输出形状 | `(B, 2, 22)` |
| 输出类型 | `torch.float32` |
| 输出设备 | 采样器配置的训练设备；输入类别应位于同一设备 |
| 行对应关系 | 输出第 `i` 行属于输入 `motion_ids[i]` 的类别 |
| 帧对应关系 | 第 0 帧在时间 `t`，第 1 帧在 `t + frame_dt` |
| 关节定义 | 与环境 `obs["amp"]` 完全一致 |

例如，输入类别 `[0, 3, 3, 5]` 时，输出四个窗口依次来自 `lefthand`、`rightjump`、`rightjump`、`rightstep`。

采样器应满足：

- 从 `artifacts/goalkeeper_k1/serial/` 读取参考 clips，不混入并联版本。
- 在对应 clip 的有效时间范围内随机选择窗口起点。
- 原始 30 FPS 数据按物理时间插值，不能将相邻原始帧直接当作相邻控制步。
- 同一窗口的两帧来自同一 clip，第二帧不能越过末尾；不首尾循环拼接，不用跨文件拼帧补齐。
- 不减默认姿态，不做统计归一化，第一版不启用随机变速或镜像。
- 类别不存在、数据缺失、特征顺序不匹配或 clip 时长不足时，应明确报错，不静默切换其他类别。

采样器同时暴露 `joint_names`，其值应与 `K1_JOINT_ORDER` 一致，供 Part A 在启动时检查。

## 自动 reset 与窗口有效性

环境自动 reset 后，`env.step()` 返回的结束环境观测可能已经属于新回合。第一版不要求提供额外的 terminal AMP observation，而采用以下规则避免跨回合窗口。

1. Part A 在 step 前保存当前类别与必要的关节历史。
2. step 后，Part A 使用 RL wrapper 返回的 `dones`，其中包含终止或截断；将其规范为 `(N,)` 的布尔 mask。
3. 对 `done=False` 的环境，使用 step 前后的关节角构造正常窗口，以 step 前保存的类别计算 AMP 奖励并入库。正常情况下类别应保持不变。
4. 对 `done=True` 的环境，不使用跨 reset 的窗口计算 AMP 奖励，也不放入 AMP Replay；该步 AMP 奖励置零，环境任务奖励和 PPO 终止处理仍正常保留。
5. 使用 reset 后的关节角重新初始化对应环境的历史，其他环境的历史不受影响。
6. 初始化时可以重复首帧填充历史，但不将该填充窗口当作真实运动样本入库；下一次有效 step 产生真实两帧窗口。

reset 后新读取的类别对应新回合。不能把旧回合类别与新回合观测组成的样本交给判别器。

## 奖励与恢复阶段

AMP 奖励由 Part A 在 Runner 中与环境任务奖励组合，Part B 不在环境 reward 字典中再次添加同一项。

Part A 负责组合权重、风格奖励尺度和日志，并与环境的 `scale_rewards_by_dt` 规则保持一致，避免重复乘或漏乘控制周期。

恢复阶段的第一版提案是：保持本回合类别至 reset，在有效的非 done 步继续计算 AMP，不因 `shot_resolved` 自动关闭全部 AMP 奖励。Part B 需先核对参考 clips 是否覆盖预期恢复动作；双方确认后固定此规则。如需阶段 mask，应另行定义它的形状、时刻和生产方，不能仅由一侧隐式改变。

## 职责与修改边界

| 工作项 | 负责部分 |
| --- | --- |
| clip 读取、插值、参考窗口采样及元信息 | Part B |
| 环境单帧 AMP 观测、类别读取、发球与 reset | Part B |
| 环境配置和 AMP task 注册 | Part B，接入 Part A 提供的 Runner 与 RL 配置 |
| 学习端 loader 适配与窗口展平 | Part A |
| 策略历史、带类别的 Replay Buffer | Part A |
| 判别器归一化、loss、更新和风格奖励 | Part A |
| 总奖励组合、PPO 集成与 checkpoint | Part A |
| reset 语义、恢复阶段规则和联合验收 | Part A 与 Part B 共同确认 |

现有 AMP 构造入口会直接创建通用 `MotionLoader`。Part A 负责学习端的接入适配，Part B 提供约定的采样接口。若确需修改公共 loader，先明确唯一修改负责人，避免两侧同时改变其特征布局。

## 接口验收与确认

接口冻结前共同确认：

- [ ] 接受本文的函数名称、张量形状、类型与设备约定。
- [ ] 关节顺序统一引用 `K1_JOINT_ORDER`，使用绝对弧度值。
- [ ] 六类标签映射固定，回合内类别保持不变。
- [ ] 参考与实际运动间隔统一使用 `env.step_dt`。
- [ ] 接受 done 步排除跨 reset AMP 窗口的第一版规则。
- [ ] 核对参考片段覆盖范围，确认恢复阶段 AMP 规则。
- [ ] 确定新接口所在模块及公共文件的修改负责人。

联合验收至少覆盖：

- 同一机器人姿态通过参考路径和环境路径生成相同的单帧特征。
- 指定类别采样的输出顺序、时间间隔与关节顺序正确。
- 单个环境 reset 时，其他环境历史不变，结束环境不存在跨回合样本。
- 标签不串类，填充窗口不作为真实策略样本入库。
- 仅新增 AMP 组和训练接口，不改变现有 Actor 与 Critic 的输入。

接口冻结后，Part A 可用模拟 expert 和环境数据推进学习端，Part B 可用模拟消费者验证真实输出。特征、类别或时间语义的后续变更需同步更新本约定和两侧测试。
